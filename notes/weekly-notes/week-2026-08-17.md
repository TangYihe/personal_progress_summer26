### New debts opened 2026-08-18

- [ ] 🔴 **Upstream report — driver has no signal handling.** `we driver` installs **no** SIGINT or
      SIGTERM handler anywhere. `Ctrl-C` goes to the whole foreground process group, so it interrupts
      the RT hardware loop (`SCHED_FIFO/20`, 100 Hz, almost always inside a blocking Gento SDK call)
      instead of going through the supervisor's cooperative stop. The idle/unlink sequence can then
      fail **silently** — errors go to a queue in a parent that is itself tearing down — leaving the
      robot energized. **Observed 08-18: needed a physical robot restart.** SIGTERM is worse (no
      handler → `finally` never runs). Only `--max-seconds` shuts down through the normal return.
      **Ctrl-C is not a stop button; the e-stop is.**

**1. The two worktrees are genuinely isolated — and the mechanism matters.**
`robo` is a single global binary; the isolation comes from `robo.nix`, which pins every venv to
`$PWD`: `UV_PROJECT_ENVIRONMENT="$PWD/.robo-nix/venvs/<profile>"`. Each tree's `we` hard-binds to its
own `src` (shebang + `.pth`), so they cannot execute each other's code.
⚠️ **But `project_root()` is cwd-first** — it checks `Path.cwd()` before walking up from `__file__`,
so running one tree's `we` from the other tree's directory loads the *wrong* `config/`. Always launch
from the tree root. ⚠️ `artifacts/` is per-tree too: the develop worktree cannot see our datasets or
checkpoints at all.

**2. Sim smoke passed first try.** `we teleop --profile keyboard --sim --headless --max-seconds 0.5`
→ 25 control ticks @50 Hz, 50 driver ticks @100 Hz, 0 errors, 0 warnings, every loss counter zero.
The run envelope (`artifacts/runs/…/summary.json`) answers "did it run correctly" without reading a
log line — this is the new debugging surface and it is good.

**3. Black MuJoCo window — resolved, no root cause, do not re-litigate.** Cost the first hour. Ruled
out *by measurement*: GL stack (offscreen render 95% non-black), `__NV_PRIME_RENDER_OFFLOAD` (a real
onscreen window renders **with** it set — the old 07-16 workaround was irrelevant here), nixGL vs
host driver (both exactly `590.48.01`), `LD_LIBRARY_PATH` GL libs (byte-identical between trees), the
`SAMPLES=4` MSAA hint (identical in both trees; 1280×720 with it renders fine), and `robo.nix`
graphics config (identical). Both trees render now. **If it recurs it is a focus/compositing thing,
not the migration.** Methodological note for next time: `import -window` on an *occluded* X11 window
returns black regardless of content, and `XRaiseWindow` is ignored by mutter — screen capture cannot
