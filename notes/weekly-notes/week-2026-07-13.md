## Plan (set 2026-07-15) — next big goal: IL / autonomous execution of the cube-twist task

> The teleop side of the two-step Rubik's-cube twist task works (vertical two-finger twist →
> horizontal twist). Next big goal: **imitation learning → autonomous execution** of it.

**Substeps:**

1. **1.a — Reset-logic change (prerequisite, needs careful design + team discussion).**
   *07-15: current mechanism mapped + design options written up →
   [design/recording-reset-pose.md](../design/recording-reset-pose.md).*
   Today pressing `r` always ramps to the default init pose (arms at side of body, pointing
   forward). The task is hard enough that episodes should instead START from a pose where the
   **left hand is already grasping the cube**. Non-trivial change touching teleop, data
   collection, AND deployment (the deploy-time reset must reproduce the same start pose, or
   we create a train/deploy mismatch). Think it through carefully and discuss before building.
2. **1.b — Collect data + train, curriculum-style.** Start with the easiest substep (left hand
   pre-grasped, right hand single-finger twist); gradually increase task complexity and see
   how far IL gets.
3. **1.c — Risk hedge: RL reading.** The task may be too challenging for pure IL — read recent
   RL-for-dexterous-manipulation works in parallel (on the other laptop → notes repo is now
   committed + pushed each session so it's readable there).
4. **2 — Data-collection bug.** Teammates report **a few seconds of data lost here and there
   during recording**. If they aren't prioritizing a fix, investigate it ourselves (it blocks
   trusting collected data for 1.b).

**Decide focus AFTER the team meeting** (see meeting prep below).
