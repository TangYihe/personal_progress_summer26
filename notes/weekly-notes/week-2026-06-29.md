**Inference/eval modes (reference — figured out 2026-07-01, running still TODO):**

Three modes, mapping onto the "training obs vs. real obs" question:

1. **`we eval` — open-loop, RECORDED obs, sim only (no robot).** Feeds recorded observations from dataset episodes → policy predicts actions → MuJoCo viewer shows predicted vs. ground-truth. Pure "did the model learn anything" check. Runs on workstation; needs only checkpoint + dataset.
   ```bash
   we eval act_pick_toy                 # play episodes in viewer
   we eval act_pick_toy --split val     # val (unseen) episodes only — the honest check
   we eval act_pick_toy --episode 3 --max-frames 300
   ```
2. **`we deploy --gt-obs` — RECORDED obs, through the real deploy stack.** Same recorded obs, but pushed through the actual deploy/command-bridge path (publishes command packets on `:5558`). Validates deploy plumbing without live sensors. `--dry-run` prints resolved settings only.
   ```bash
   we deploy act_pick_toy --gt-obs --dry-run
   we deploy act_pick_toy --gt-obs
   ```
3. **`we deploy --live` — REAL obs, closed loop on the robot.** Queries live driver snapshot for real robot state + camera, runs policy, publishes commands back. Needs the driver running on Orin. This is tomorrow's full-pipeline piece.
   ```bash
   we deploy act_pick_toy --live --driver-address 6.6.7.100:5559
   ```

**⚠️ Two subtleties:**
- **Config defaults `deploy.gt_obs: true`** (`config/policy/act_pick_toy.yaml`). So a bare `we deploy act_pick_toy` runs the RECORDED-obs check, NOT live. Must pass **`--live`** for the real robot.
- **All modes open a MuJoCo viewer → need a display.** Same failure class as the rerun `xlib` error. Run **physically at the workstation** (`robo shell -p operator`), not headless SSH. Inference is workstation-side; deploy binds `:5558`, Orin driver connects to it (same spot as the teleop operator).
